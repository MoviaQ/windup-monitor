# Iteracja S1 — dowód end-to-end (2026-10-19)

> Dokument historyczny: ówczesna nazwa produktu „StatusPilot”; obecnie **Windup Monitor** (UI: **wind-up monitor**). Nazwy baz/ścieżek w treści są historyczne i pozostają bez zmian dla zgodności.

Pierwsza iteracja doprowadza slice S1 do realnego działania:
prawdziwa binarka Go → prawdziwy Core (prod `dist`) → prawdziwy PostgreSQL
→ uwierzytelnione dashboard API + SPA z tego samego origin.

## 1. Zakres

Zrealizowane w S1: bootstrap/login (argon2id, sesja, CSRF+Origin,
rate-limity), pairing/enroll (token 15-min single-use, credential pokazywany
raz, hash w DB, plik 0600), heartbeat v1 (`seq` + idempotencja, transakcja
`ReadCommitted` + `SELECT … FOR UPDATE`, re-autoryzacja pod blokadą,
brak nadpisywania nowszego starszym, `late`, `CONFIG_STALE`),
dashboard API (`GET /agents`, `GET /agents/:id/metrics` bounded),
rotacja/revokacja credentialu (**API + CLI**; UI rotacji brak → SP-105b),
health/ready, redakcja sekretów w logach.

Semantyka bezpieczeństwa (po poprawkach review, `core/CONTRACT.md` §3):
dual-accept do `overlap_until`; retry `rotate` przy pending idempotentny
(`200`), inny `next` przy pending → `409 ROTATION_CONFLICT`; retry `rotate`
po zakończonej rotacji → `409` bez odtwarzania pending; repeat
`rotate_confirm` → `200`; promocja po deadline także przy pierwszym żądaniu
ze starym/błędnym Bearerem (stary sekret → `401`); autoryzacja sprzed
confirm/deadline/revoke nie uprawnia do zapisu; revoke terminalny
(`401 AGENT_REVOKED`, czyści oba hashe). Focused security review:
brak HIGH/MED.

Celowo poza S1 (bez kodu): Docker discovery/status, HTTP checks, incydenty,
kolejka komend/recovery, rollupy/retencja/joby, PWA service worker,
powiadomienia/webhooki, AI, multi-user, 2FA, reset hasła CLI (SP-600).

## 3. E2E prawdziwą binarką (`scripts/e2e-go-core.mjs`, 24 kroki)

dev ani review nietknięte), Core z produkcyjnego `dist`
(`NODE_ENV=production`) na `127.0.0.1:18081`, `WEB_DIST_DIR=web/dist`,
interwał heartbeat 5 s. Przebieg z 2026-10-19 (po wszystkich fixach):

1. isolated e2e database created
2. migrations applied to e2e database
3. core + web built from source
4. real Go agent binary built
5. Core ready (real HTTP, production dist)
6. fresh instance reports initialized=false
7. bootstrap created admin + session cookie
8. bootstrap token is single-use (replay → 409)
9. session + CSRF token issued
10. invalid auth (401) / missing CSRF (403) / foreign Origin (403) rejected
11. pairing token issued
12. Go binary enrolled (one-time token consumed)
13. credential stored 0600
14. Go binary ran continuous heartbeats without exiting (~21 s, 5 próbek)
15. dashboard API lists the Go agent as **online** with real host metrics
    (CPU/RAM/dysk/sieć/uptime z `/proc` hosta)
16. metrics history holds 5 real samples (ascending, bounded)
17. PostgreSQL holds 5 `metric_samples` rows for the agent
18. reconnect resumes with persistent seq (**5 → 8**), no `STALE_SEQ` w logu
19. duplicate envelope rejected (`409 STALE_SEQ`), wierszy w DB bez zmian
20. bad credential / unknown agent rejected (401 `BAD_CREDENTIAL`)
21. revocation is immediate (`401 AGENT_REVOKED`), dashboard: `revoked`
22. production SPA served by Core on the same origin (`<div id="root"`)
23. logout destroys the session (`/auth/me` → 401)
24. no secrets in Core/agent logs (grep po pełnych logach przebiegu)

Stale/offline bez sleepów: `core/test/status.test.ts` manipuluje

## 6. Ograniczenia i znane problemy

1. **Budowa obrazu Compose i `up --build` niewykonane tutaj**: wolne ~0,5 GB
   na `/` (spadło w trakcie sesji — buildy `tsc`/`vite`/`go`), brak obrazu
   `node:22-alpine` w cache, obce usługi na tym samym Dockerze.
   Ryzyko zapchania dysku > wartość testu. Pokrycie równoważne: prod `dist`
   + `migrate deploy` + healthcheck w E2E i stacku review; `compose config`
   (oba pliki) valid. Do wykonania na hoście z zapasem miejsca.
   (Uwaga: na tym hoście działa tylko `docker-compose` v1, nie wtyczka
   `docker compose` — README odnotowuje obie formy.)
2. Rate-limity są in-memory (restart zeruje); promocja rotacji po deadline
   jest leniwa (brak joba `state_sweeper`); audyt `audit_log` bez
   egzekwowania roli DB (aplikacja nie robi UPDATE/DELETE) — wszystko
   udokumentowane w README „Ograniczenia S1".
3. UI rotacji credentialu nie istnieje (tylko revoke + API/CLI rotacji) →
   split SP-105 (kanban): SP-105a Done, SP-105b Backlog.
4. Wcześniej obserwowana „flakiness" `credential-races.test.ts` to były
   kolizje z równoległymi procesami vitest na wspólnym pliku
   `core/.tmp/test/bootstrap-token` (osobna DB nie wystarczała) —
   naprawione w §5; dowód: 2 równoległe pełne suity 52+52 zielone.
   Pojedynczy przebieg 52/52 również zielony.
5. **Visual review — niepotwierdzone w tym przeglądzie** (uczciwie):
   kopiowanie tekstu do schowka (clipboard) w trybie headless nie zostało
   potwierdzone; badge/statusy `pending` (rotacja), `revoked`, `stale`,
   `offline` nie były renderowane live na żywym stacku — na żywym stacku
   widoczny był `online`, stan `offline` sprawdzono symulacją sieciową,
   a pozostałe stany są pokryte automatycznymi testami (etykiety w testach),
   nie zrzutami. To ograniczenie review, nie twierdzenie, że stany działają
   „zobaczone na żywo".
6. **Docker build i zdalne CI nadal niewykonane** (szczegóły §2 i §1) —
   jawnie jako follow-up SP-107 w kanbanie, bez twierdzenia, że pełne
